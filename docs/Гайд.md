# Гайд: приложения семьи — пользоваться и сделать свою копию

Для друзей, которым отдают приложения семьи (этап 7 Штаба: Ш-129, Ш-132, Ш-135). Два уровня:

- **Пользоваться** — открыть приложение по нашему адресу и вести свои записи. Программировать не нужно.
- **Своя копия** — форк приложения на своём GitHub: свой адрес и свои доработки, при желании — агентами (их гайд — в `goigolden88/Skills_Claude`, `docs/гайд-агентов.md`).

Начни с первого, даже если собираешься делать второе: так ты увидишь приложение до того, как его менять.

## Приложения

Все — local-first: данные лежат на твоём устройстве, в браузере, и работают без сети. Своего сервера у приложений нет, мы твоих записей не видим.

| Приложение | Адрес | Что делает |
|---|---|---|
| «Делу Время» | `goigolden88.github.io/DeluVremya/` | Входящие, план дня, учёт времени, обзор недели |
| «Трапеза» | `goigolden88.github.io/Trapeza/` | Что съедено, в каком приёме, совпала ли неделя с намеченным |
| «Злотые» | `goigolden88.github.io/Zloty/` | Доходы и расходы, долги, сбережения |
| «Дневники» | `goigolden88.github.io/Dnevniki/` | Обслуживание (дом, техника, авто), здоровье, вещи |
| «Тотальный Учёт» | `goigolden88.github.io/TotalUchet/` | Сводка по остальным: читает их итоги |

Первым ставь «Делу Время» — в нём больше всего экранов. Остальные — когда первое прижилось.

«Фишки» (`goigolden88.github.io/Magic_Fishki/`, учёт покерных вечеров) — не из семьи: синхронизации и общего ядра у них нет, этот гайд к ним — только в части «Установить на iPhone».

## Пользоваться

### Вместе с Claude — если не хочется разбираться самому

Шаги ниже можно пройти с Claude (claude.ai или приложение Claude — хватит бесплатного): он читает этот гайд, ведёт по шагу за раз и спрашивает только нужное. Удобнее с компьютера: Claude в одном окне, браузер в другом. Вставь ему, заполнив `<…>`:

```
Помоги мне поставить приложение «<название>» и настроить синхронизацию
по гайду: https://github.com/goigolden88/FamilyCore/blob/main/docs/Гайд.md
Прочитай раздел «Пользоваться» целиком и веди меня по нему.

Устройство: <iPhone / Mac / Windows / Android>, браузер: <Safari / Chrome>.
Аккаунт GitHub: <есть / нет>.

Как вести:
- по одному шагу; жди, пока я напишу, что сделал или что вижу на экране;
- спрашивай только то, без чего не обойтись;
- кнопки называй как в гайде; если у меня на экране иначе — спроси,
  что я вижу, и не выдумывай;
- токен GitHub в чат не проси и не повторяй: я копирую его сам —
  в менеджер паролей и в приложение;
- в конце проверь со мной, что в «Настройки» → «Синхронизация»
  появился «Последний обмен».
```

Если Claude пишет, что ссылку открыть не может, — скопируй ему текст гайда целиком.

Токен — единственное, что Claude видеть не должен: с ним можно читать и менять твои записи. Поэтому Claude ведёт, а нажимаешь ты, — даже если твой Claude умеет сам управлять браузером. Страницу с токеном не показывай ему и на скриншоте.

### 1. Установить — первым делом

**iPhone и iPad** — только через Safari:

1. Открой адрес приложения в Safari.
2. «Поделиться» (квадрат со стрелкой) → «На экран „Домой“» → «Добавить».
3. Дальше открывай приложение **иконкой**, а не вкладкой Safari.

Это не украшение. Сайт, открытый во вкладке Safari, iPhone стирает через 7 дней без посещений — вместе с записями. У установленного приложения хранилище своё и не стирается. Приложение само подскажет то же самое, пока не установлено.

**Android** — Chrome: меню → «Установить приложение» (или кнопка в самом приложении).

**Компьютер (Mac, Windows)** — лучше **Chrome** (или Edge): кнопка «Установить» в самом приложении или значок установки в адресной строке. Firefox ставить приложения не умеет.

**Mac — Safari** (macOS 14 Sonoma и новее) — тоже можно, но иначе:

1. Открой адрес в Safari → меню «Файл» → «Добавить в Dock» → «Добавить».
2. Открывай приложение из Dock, а не вкладкой: вкладку Safari на Mac, как и на iPhone, стирает через 7 дней без посещений.
3. Приложение в Dock не делит данные с Safari и с другими приложениями из Dock — как на iPhone, токен синхронизации вписывается в каждое (шаг 3).

Начинать можно с любого устройства. Второе — телефон или компьютер — подключается синхронизацией, записи придут сами («Второе устройство» в шаге 3).

### 2. Посмотреть на демо (по желанию)

На первом экране приложение один раз предложит «Посмотреть на демо-данных?». Это отдельная база с выдуманными записями: можно нажимать что угодно. Выход — «Настройки» → «Выйти из демо»: всё, что записано в демо, стирается, твои настоящие записи не трогаются. Предложение не появится, если синхронизация уже настроена.

### 3. Синхронизация — сразу

Синхронизация — это копия твоих записей в твоём **приватном** репозитории на GitHub. Она же страховка: потерял телефон — данные на месте. Настраивается один раз на приложение, дальше работает сама.

Что понадобится: аккаунт GitHub (бесплатный) и менеджер паролей (на iPhone и Mac подойдёт встроенный «Пароли»).

**Репозиторий данных** — один на приложение:

1. github.com → «+» → «New repository».
2. Имя — например, `DeluVremyaData`. **Private** — обязательно. Остальное не трогай: пустой репозиторий подходит, первый файл приложение положит само.

Одному приложению — один репозиторий. Два приложения в один репозиторий не пишут: приложение видит чужой репозиторий и останавливается, ничего не испортив.

**Токен** — ключ, которым приложение пишет в этот репозиторий:

1. github.com → фото профиля → «Settings» → «Developer settings» → «Personal access tokens» → **«Fine-grained tokens»** → «Generate new token».
2. Имя — например, «семья». Срок — год (за 30 дней до конца «Настройки» предупредят).
3. «Repository access» → **«Only select repositories»** → выбери репозиторий данных.
4. «Permissions» → «Repository permissions» → **«Contents» → «Read and write»**. Больше ничего не включай.
5. «Generate token» → скопируй `github_pat_…` **сразу в менеджер паролей**: GitHub покажет его один раз.

Токен никуда не пересылай — ни в сообщении, ни в заметке, ни в QR. С ним можно читать и менять твои записи.

**Вписать в приложение:** «Настройки» → «Синхронизация» → репозиторий в виде `твой-логин/DeluVremyaData` и токен → сохранить. В «Синхронизации» появится «Последний обмен» — значит, работает.

**Следующее приложение:**

1. Новый приватный репозиторий данных (`TrapezaData`…).
2. Тот же токен: github.com → «Fine-grained tokens» → твой токен → «Edit» → добавь новый репозиторий в «Only select repositories». Перевыпускать не нужно.
3. Вписать в новое приложение.

На **iPhone** и в **Safari на Mac** (приложения в Dock) токен и имя репозитория вписываются **в каждое** приложение отдельно: у каждого установленного приложения своё хранилище. В Chrome и Edge — на Android и компьютере — приложения с одного адреса видят друг друга: токен вписывается в одном — остальные берут его сами, нужно только имя своего репозитория.

**Второе устройство** — то же: установить, вписать репозиторий и токен; записи придут сами. Правки с двух устройств сливаются по записи, побеждает более поздняя.

### 4. Копия файлом

Синхронизация — главная копия. Файлом — запасная, и единственная, если синхронизации нет: «Настройки» → «Экспорт и импорт» → «Сохранить в файл» или «Поделиться». Без синхронизации заголовок «Экспорта и импорта» краснеет, когда пора сохранить. Вернуть — там же, «Восстановить из копии».

Очистка данных сайта в браузере стирает всё, что не в копии.

### 5. Что ещё полезно знать

- **Обновления** приходят сами — в тот день, когда мы их выпускаем. Что изменилось — экран «Что нового».
- **Справка** — в каждом приложении: где лежат данные, синхронизация, импорт из таблиц и заметок через ИИ.
- **Напоминания** работают только у установленного приложения в Chrome на Android. На iPhone их нет.
- **Ошибка** — «Настройки» → «О приложении» → «Сообщить об ошибке»: соберёт текст, который можно прислать нам.

## Своя копия

Форк — твоя копия приложения на твоём GitHub: свой адрес, свои доработки, наши обновления — когда сам захочешь. Код открыт под лицензией MIT: можно менять и распространять, сохранив файл `LICENSE`.

### 1. Форк и свой адрес

1. Страница приложения на GitHub (например, `github.com/goigolden88/DeluVremya`) → «Fork». **Имя оставь прежним**: адрес сборки зашит в `vite.config.ts` (`BASE = '/DeluVremya/'`); другое имя — поменяй и там.
2. В форке — вкладка «Actions» → «I understand my workflows, go ahead and enable them»: у форка автоматизация выключена, пока не включишь.
3. «Settings» → «Pages» → «Source» → **«GitHub Actions»**.
4. «Actions» → «Деплой на GitHub Pages» → «Run workflow». Через пару минут приложение — на `твой-логин.github.io/DeluVremya/`. Дальше каждый `push` в `main` выкатывается сам.
5. **«Агенты»** — workflow для агентов, которые сами пишут код по задачам. Пока ты их не подключил (гайд агентов), выключи: «Actions» → «Агенты» → «…» → «Disable workflow». Иначе при слиянии PR он будет падать без ключа подписки.

У копии свой адрес — значит, своё хранилище в браузере, пустое. Записи из нашего адреса переносятся синхронизацией: впиши в свою копию тот же репозиторий данных и токен — записи придут. Если ты поменяешь в копии схему данных, приложение по нашему адресу увидит более новую версию в репозитории и остановит синхронизацию со словами «обнови приложение» — данные не испортятся, но этот репозиторий станет только твоей копии.

### 2. Ядро

Общая часть всех приложений — ядро `FamilyCore` — лежит в копии подмодулем (ссылкой на другой репозиторий) в `src/shared`. По умолчанию ссылка — на наш `goigolden88/FamilyCore`.

- Наши исправления ядра приходят PR от Dependabot (бот GitHub, который сам поднимает версии). У форка Dependabot может быть выключен: если его PR не появляются — включи его в настройках репозитория (раздел «Code security») или поднимай ядро руками: `git submodule update --remote src/shared`, проверки, коммит.
- Хочешь менять само ядро — форкни и `FamilyCore`, а в `.gitmodules` своей копии поменяй адрес на свой.
- `src/shared` правится только в репозитории ядра, не в копии приложения: следующий подъём ядра затрёт правку.

### 3. Работать с кодом

Сначала поставь на компьютер:

- **git.** На Mac — в «Терминале» `xcode-select --install` (поставит git вместе с инструментами Apple). На Windows — git-scm.com.
- **Node.js 24** — на ней собирают и проверяют приложения на GitHub. nodejs.org → «Download» → выбери версию 24 (по умолчанию сайт может предлагать более новую). Проверка: `node -v` пишет `v24…`.

Дальше — в «Терминале» (на Windows — PowerShell):

```
git clone --recurse-submodules https://github.com/твой-логин/DeluVremya
cd DeluVremya
npm ci
npm test && npm run build
npm run dev
```

В `src/shared` `npm install` не запускается: появится вторая копия React, и приложение сломается.

Правила проекта — в его `CLAUDE.md` и `docs/`: модель данных, решения и почему так. Им подчиняется код, их же читает агент.

### 4. Стартовый промпт для агента

Для Claude Code (в браузере — claude.ai/code, или на компьютере) с подключённым форком. Первая сессия — разговор, не код:

```
Это мой форк приложения «<название>» (<твой-логин>/<репо>), сделанный из
goigolden88/<репо>. Прочитай CLAUDE.md, docs/04-Журнал.md, docs/03-План.md
и docs/02-Архитектура.md. Ядро — подмодуль src/shared (FamilyCore): там не
правь, npm install не запускай.

Я хочу: <что поменять под себя>.

Сначала расскажи простыми словами, как устроено то, что я хочу поменять,
и предложи план — по шагам, с тем, что может сломаться (данные на
устройствах, синхронизация, схема данных). Код — после моего «да».
```

Правка, которая меняет хранимые данные (новые хранилища, поля, версия схемы), — самая рискованная: перед ней — копия файлом и проба на копии своих данных.
