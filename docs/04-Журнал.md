## 18.09.2026 — Сопровождение: находки перевода «Трапезы»; `db` приложения подходит под контекст

Первая сессия сопровождения — по передаче Б2 «Трапезы» (ветка `familycore` «Трапезы», подмодуль на `981200e`). Три находки; одна блокировала перевод. В `src/shared` «Трапезы» ничего не правилось. Перевод «Трапезы» лежит незакоммиченным в её рабочей копии, поэтому её употребления читались с диска — только поиском, не сравнением.

**Находка 1 — `db` приложения не подходил под `SharedDb`. Закрыта, `d1f282f`, API не менялся**

- **Воспроизведено на «Полке»** пробным файлом: `createDb(shelf)` в `SharedDb` — та же ошибка, что у `tsc` «Трапезы»: `ChangeEvent<ShelfStores>` не подходит под `ChangeEvent`. `createSync(shelf, db)` в `Sync` и `shelf` в `SharedConfig` подходили
- **Что это** — ошибка типов ядра, не шва. По полям событие приложения под общее подходит: `ChangeEvent<StoreMap>.store` — `string`. Но компилятор сравнивает обобщённый `ChangeEvent<R>` по параметру и из-за `keyof R` требует `StoreMap` не уже таблицы приложения. Я-03 хотел ровно того, что написано в `ui/core.tsx`, — типы без таблицы хранилищ; `ChangeEvent` с умолчанием эту цель не выполнил, а тест, кладущий настоящий `createDb` в `SharedDb`, в Этапе 1 не написан
- **Починка** — в `SharedDb.onChange` событие описано без обобщения: `{ store: string; origin; count }`. `ChangeEvent<R>` в `core/db.ts` не тронут: приложение по-прежнему видит свои имена хранилищ в своих подписчиках. Отвергнуто: `ChangeEvent.store: string` у всех — смена API ради того же итога, приложения теряют проверку имён
- **Решения Я-NN нет:** общий интерфейс стал принимать шире, API приложений тот же (`06-Процесс`, передача, п. 3)
- **Проверка до правки** — `ui/core.test.ts`: `{ config: shelf, db, sync } satisfies Core`, отдельным коммитом `c734e0b`. До правки `npm run typecheck` — код 1 с той же ошибкой; после — 0

**Находка 2 — `useFeed` отдаёт `FeedItem` со строковым `kind`. Не правится**

Строка — правильная граница. `FeedItem.kind` — строка по договору семьи; `compareFeed`, `groupFeed`, `filterFeed` берут `FeedItem` со строкой; `feedItems` «Трапезы» и так отдаёт `FeedItem[]`. Параметр вида сузил бы только подпись вида, а ей всё равно подписывать незнакомый вид как есть. `kindLabel(kind: string)` «Трапезы» — верная форма.

**Находка 3 — `ImportRecords` ставит `intro` только перед общим абзацем. Не правится**

Порядок «своё — потом общее» правильный: `intro` — слова приложения, что сюда загружают; общий абзац — механика, одинаковая у всех. Слот «после» появился бы ради одной фразы одного приложения — правило границы. У «Трапезы» абзац Р-21 «Трапезы» теперь стоит над «Файл готовится по промпту…», текст тот же.

**Непереведённые копии.** У «Делу Время» на `d86f0aa` и «Дневников» на `a913dcb` (сверено через `git show`) `db` — одиночка модуля, `ChangeEvent` не обобщён (`store: SyncedStore`), `useFeed` импортирует `db` напрямую. Контекста и `SharedDb` нет — беды нет.

**Состояние**

*Проверено машинно:* `npm run typecheck` — 0; `npm test` — 0, 20 файлов, 326 тестов; CI «Проверка ядра» — в итоге сессии.

*Не проверено:* `tsc` «Трапезы» без приведений после обновления указателя — хвост в Плане.

**Не описано в документах — на обсуждение**

- **Предупреждение Р-21 «Трапезы»** («записи загружай на одном устройстве — остальные получат синхронизацией») верно, вероятно, для любого приложения, чей импорт даёт записям новые случайные id. У «Делу Время» и «Дневников» его нет. Если оно общее — место ему в общем абзаце `ImportRecords`, и тогда это правка ядра для всех, а не слот
