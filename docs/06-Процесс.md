### Приложения — только читать

Из репозиториев приложений ничего не правится и не коммитится, даже найденная ошибка: о ней говорится человеку. Перевод приложения на ядро и обновление указателя подмодуля — сессии **из корня того приложения** (Р-49 «Трапезы»).

**Сравнивать копии — только через `git show`** объектов git, никогда по файлам с диска: `core.autocrlf=true` разворачивает рабочие копии в CRLF, и «Дневники» с диска выглядят целиком «иными» (Журнал «Трапезы», 18.09.2026, ошибка по ходу).

## Раздача и обновление

Ядро раздаётся подмодулем git (Р-46 «Трапезы»). Версия ядра у приложения — коммит, на который указывает подмодуль; он лежит в дереве приложения и виден в диффе.

**Подключение** — один раз, при переводе приложения, из его корня:

```
git submodule add https://github.com/goigolden88/FamilyCore.git src/shared
```

и в `.github/workflows/deploy.yml` приложения у `actions/checkout` — `submodules: true`. Без этой строки деплой соберёт приложение без ядра.

**Клон приложения** — только `git clone --recurse-submodules`. Уже склонированное без него: `git submodule update --init`. Иначе `src/shared` — пустая папка, и сборка падает непонятной ошибкой.

**Правка ядра — всегда два коммита в двух репозиториях:**

1. Сессия **из корня `FamilyCore`**: правка, тесты на подставном конфиге, `npm test` и `npm run typecheck` по коду выхода, запись в Журнал ядра, коммит, пуш. CI ядра (Я-04) обязан быть зелёным
2. Сессия **из корня приложения**: `git submodule update --remote src/shared`, прогон приложения — тесты, сборка, `smoke` — и коммит указателя. Забытый указатель означает, что правки нет ни у второго устройства, ни в CI

Правка ядра, сделанная в `src/shared` приложения «на месте», — это тоже коммит в ядро: он делается в подмодуле и пушится в `FamilyCore` до коммита указателя. Но по умолчанию правка ядра идёт сессией отсюда.

**Перед пушем приложения** — `git status` чистый **и в подмодуле тоже**: `git -C src/shared status`.

**В `src/shared` приложения не запускать `npm install`** (Я-02): появится `src/shared/node_modules` со второй копией React.

**Правка ради одного приложения — повод остановиться.** Либо это параметр в `AppConfig` или аргумент, осмысленный для любого приложения семьи, либо это не ядро. Решение — здесь, Я-NN, до кода.

**Поломка в ядре чинится один раз, здесь.** Приложения получают её обновлением указателя; непереведённые (со своей копией ядра) — отдельными сессиями из их корней, и про каждую копию говорится человеку.

**Откат** у приложения — вернуть указатель подмодуля на прежний коммит: одна строка в диффе.

## Токены семьи (Я-25)

Делает человек, на GitHub — от аккаунта-владельца репозиториев данных (`goigolden88`). Репозитории данных на 24.09.2026: `DeluVremyaData`, `TrapezaData`, `dnevniki-data`, `ZlotyData`.

**Токен «семья» — у приложений, свой на каждом устройстве:**

1. Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
2. Имя — по устройству: «семья — телефон», «семья — ноутбук». Resource owner — владелец репозиториев данных. Срок — выбрать и запомнить дату
3. Repository access → **Only select repositories** → **только репозитории данных**. Ни `FamilyCore`, ни репозиториев кода приложений, ни `TotalUchet`
4. Permissions → Repository permissions → **Contents: Read and write**. Metadata: Read-only GitHub ставит сам. Больше ничего
5. На этом устройстве в каждом приложении: «Настройки» → «Синхронизация» — вставить токен, имя репозитория не трогать, дата «когда истекает» — та, что показал GitHub. **«Проверить доступ»** — сверить полное имя репозитория: своё ли. «Синхронизировать»
6. Так же — на каждом устройстве, своим токеном
7. **Когда все устройства переведены — отозвать прежние токены по приложению** (Fine-grained tokens → Delete). Иначе они живут до своего срока

Ошибка в имени репозитория с общим токеном больше не упирается в 404: синхронизация останавливается словами «данные другого приложения семьи» (Я-24) — ничего не скачано и не отправлено. Поправить имя.

**Новое приложение** («Дача») — его репозиторий данных дописывается в Repository access каждого токена «семья» (Edit у токена), новый токен не нужен. `meta.json` с `app` оно кладёт с первого прохода.

**Токен чтения метаприложения** — отдельный, свой на каждом его устройстве: те же шаги, но **Contents: Read-only**, те же репозитории данных. Выпускается, когда «Тотальному Учёту» нужно читать срезы — его Этап 1.

## Разделение работы

**Claude Code — и «что строить», и «как».** Развилки шва и договора — тоже здесь: он видит настоящие файлы всех приложений и проверяет факты. Режим планирования — когда обсуждаем и ничего не трогаем.

**Чат (Claude Desktop, claude.ai) — когда компьютера нет под рукой.** Из чата в репозиторий приходят готовые куски markdown и список того, что переделать в коде.

## Правила ведения документов

- **Не менять задним числом.** Отмена решения — новая запись со ссылкой
- **Решения записываются в момент выбора**, номером Я-NN (Я-01)
- **Журнал обновляется в конце каждой сессии**
- **Перед пушем — `npm test` и `npm run typecheck`**, итог по коду выхода, а не grep'ом по выводу
- **План содержит только предстоящее**
- **Строки «Что нового» у ядра нет.** Видимое человеку изменение ядра попадает в `changes.ts` каждого приложения, когда оно обновляет указатель
- **Правки файлов с кириллицей** — инструментом правки или скриптом-файлом из папки сессии, не heredoc Bash с шаблонными строками JS: он съедает `\n` (опыт «Трапезы»)

### Передача в следующую сессию

Переписывается в конце каждого этапа. Сейчас — 24.09.2026: «Трапеза», «Злотые», «Делу Время» на ядре, «Дневники» переводятся последними, сессией из своего корня (Р-49 «Трапезы»). Сюда приносят то, что переводы и приложения нашли в ядре. Сессия ядра — **сопровождение**: одна беседа на пачку находок, а не на каждую.

**Правка договора** (Я-09 — пример) — релиз на все приложения: итог сессии называет каждое переведённое приложение, даже если кода у него не меняется, и проверяет это на нём — `git archive HEAD` приложения в папку сессии, новое ядро в его `src/shared`, `node_modules` копией, не ссылкой; `tsc`, тесты с `--cache=false` и сверка того, что правка задела, со старым ядром — в той же копии.

```
Проект `FamilyCore` — общее ядро семьи local-first приложений: «Трапеза»,
«Злотые», «Делу Время», «Дневники». Работать в корне
`C:\Ф\Prognananda\Claude Projs\FamilyCore`.

Прочитай `CLAUDE.md` и все файлы `docs/` перед началом. Сверь Журнал
и План: что открыто в «Хвостах закрытых этапов».

Эта сессия — сопровождение ядра: баги, нехватка параметров, швы, которые
нашли при переводе приложений в их корнях. Ядро — эталон (Р-49
«Трапезы»): чинится здесь один раз, приложения получают правку
обновлением указателя подмодуля.

Что принесено (от человека, из Журналов приложений):

 и строка в src/shared, строка Журнала приложения>

Порядок для каждой находки — сначала план по всем, код после
подтверждения:

1. **Воспроизвести в ядре, не поверить на слово.** Падающий тест на
   «Полке» (`testing/shelf.ts`): новая форма хранилища — новое хранилище
   «Полки», а не имена настоящего приложения. Без приложения не
   воспроизводится — читать его код через `git show`, не по файлам
   с диска; сказать человеку, что снять.
2. **Назвать, что это**, словами, до правки:
   — ошибка механики ядра — чинится, API не меняется;
   — не хватает параметра — это поле `AppConfig` или аргумент, только если
     он имеет смысл для любого приложения семьи;
   — это не ядро — возвращается приложению, и ядро не правится;
   — это правка договора семьи (`Base`, `FeedItem`, раскладка,
     `schemaVersion`) — только решением и как релиз на все приложения
     (Р-51 «Трапезы»).
   Если причина — прежнее решение, скажи, какое. Отменить его можно только
   новой записью.
3. **Решение Я-NN до кода**, если меняется шов, договор, состав ядра или
   API, которым пользуются приложения. Чистая починка без смены API
   решения не требует, но идёт в Журнал.
4. **Починка вместе с проверкой, которая падала до неё.** Сначала тест,
   потом правка.
5. **Правка меняет API** (имя, аргумент, проп, поле `AppConfig`) — перечисли
   до кода, что обязано поменяться у каждого переведённого приложения,
   и допиши это в `02-Архитектура`, «Как приложение подключает ядро».
6. `npm run typecheck` и `npm test` — итог по коду выхода; коммит, пуш;
   CI «Проверка ядра» зелёный. `gh` нет, итог смотреть через
   api.github.com без токена.

Итог сессии для человека — по каждой находке:

Чего здесь не делается: правка любого приложения, коммит указателя

Как работаем: сначала план работ, код после подтверждения. Решения —
в `docs/05-Решения.md` в момент выбора. В конце — Журнал, передача
```
