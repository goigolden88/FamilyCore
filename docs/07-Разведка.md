## 3. Готовые итоги — чистые функции

У всех четырёх итоги посчитаны чистыми функциями без React и без `db`, покрыты тестами. Исключение нашла вычитка: итог «Месяца» «Злотых» склеивает экран. Различаются **зерно** — за какой отрезок — и форма.

Основания по дням здесь нет |
| | `weekSummary(intake, dishes, categories, day, today)` | **только неделя** — `weekPeriod(day)` | то же за неделю + основание по дням `logged` из `elapsed` — «учёт в 6 днях из 7»; `days[].meals` — сколько блюд в каждом приёме каждого дня, единственный машинный ответ «какие приёмы были»; `days` у групп и категорий состава — «в скольких днях». ## 4. «Требует внимания» — темы напоминаний

Форма у всех одна — `Topic` ядра: `{ notice: { title, body } | null, tag, target, loudKey, quietKey }`. Тем восемь:

| | Тема (`tag`) | Когда говорит | Читает сверх записей |
|---|---|---|---|
| «Трапеза» | `day` | вчера нет записи хотя бы одного из завтрака, обеда, ужина без отметки «не было» — **или** сегодня нет ни одной записи (Р-30 «Трапезы»); перекуса у темы нет | **«не было» — отметки этого устройства**, живут два дня (`SKIPPED_KEY`, Р-29 «Трапезы»); отметки только глушат: без них тема ошибается в одну сторону — лишнее «вчера не записан обед» |
| «Делу Время» | `day` | за сегодня нет ни одного блока | имя экрана устройства — **только в тексте** (Р-26 «Делу Время»); говорит ли тема, от устройства не зависит. Зависит другое: идущий таймер лежит в `settings`, а не записью (Р-18 «Делу Время») — пока он идёт на телефоне, срез скажет «ничего не учтено» |
| | `review` | воскресенье и понедельник, обзор недели не проведён | — |
| «Дневники» | `overdue` | просрочено в циклах | — ; текст несёт **названия позиций** |
| | `illness` | открыт эпизод болезни | — ; текст несёт **название эпизода — диагноз** |
| | `content` | зависло в «смотрю» — **не чаще раза в неделю** | от устройства зависит только **когда спросить** — день прошлого вопроса; **что сказать** — по записям, признак жизни `updatedAt` синхронизируется |
| «Злотые» | `month` | с 3-го числа за прошлый месяц нет ни одной записи — слабый факт; крепче — `recordedThrough`, по какое число доведены выписки | — |
| | `recurring` | регулярные этого месяца ждут | — |

Фоновую проверку браузер будит сам, примерно раз в сутки, время выбрать нельзя (`notify.ts` ядра). Что он будит приложения одного origin разом — вывод из наблюдения человека (четыре уведомления в одно время), а не из кода. Окно со звуком — `DEFAULT_WINDOW` 12…20, у каждого приложения своё.

**Для общего напоминания через метаприложение это главное:** от настроек устройства, которые не синхронизируются, зависит одна тема «Трапезы» — что сказать — и одна тема «Дневников» — только когда спросить; у «Делу Время» от устройства зависит только текст темы `day`, но идущий таймер — не запись. Срез, посчитанный на одном устройстве, у другого скажет иное. Сверх тем у «Делу Время» от устройства зависят пороги обзора `reviewStaleDays`, `reviewGoalDays` — а от них `staleTasks` и `stuckGoals` (Р-48 «Делу Время»).

## 5. Лента

`registry.feedItems` есть у всех четырёх и отдаёт `FeedItem` договора. У «Злотых» — `feedItems(data)` без дня, у остальных — `(data, day)`; у «Делу Время» `day` строки не читают. Для хроники годится; считать по ней нельзя (`02-Архитектура`, «Срез итогов — строится»).

## 6. Правила показа чисел — к ним пришли все четыре независимо

| Правило | «Трапеза» | «Делу Время» | «Дневники» | «Злотые» |
|---|---|---|---|---|
| **Число — вместе с основанием** | Р-01: `KcalSum`, «учёт в 6 днях из 7» | `MARKS_BASIS`, `PLAN_FACT_BASIS`, `YEAR_NORMS_BASIS` | Р-38, Р-44: сумма с числом отметок, среднее с числом оценённых | Р-07: `Sum.entries`, «по 142 операциям» |
| **Неизвестное — не ноль** | **день без записей — неизвестен** (Р-24 «Трапезы»): «не учитывал» и «не ел» различаются; ккал без данных — вне суммы и названы | **модель не различает «не учитывал» и «не делал»**: минуты категории без основания `days` из `elapsedDays` в срезе соврут. Неизвестным названы `capturedOn: null`, неизвестная категория, «неучтено» — от прошедшей части окна дня (Р-21 «Делу Время») | отметка без цены — не ноль, а разница `marks − priced` (Р-38); `null` вместо числа у средней и медианной длительности, дней без болезни, средней оценки, ряда измерения; контент без даты не пишется в «начато»; ручной интервал и интервал по истории лежат рядом — `byHistory` (Р-29) | «доход не внесён» вместо нуля; без курса — вне итога и названо (`missing`) |
| **Третий исход «не ясно»** | `Verdict 'open'` — дни без записей | нет: день без блоков — день без занятия. Ближе всего — неделя не в счёт (`WeekMark.counted`: не закончилась, раньше первого блока или `since`) и `enough` у истории. Неокончательность — наполовину экранная: «ещё идёт: N дней из M» — `runningText` экрана, в итоге только `elapsedDays`; ретро-ввод меняет прошлую неделю (Р-19 «Делу Время») | статус цикла `unset` — «срок не ясен, отметок N из 4» (Р-27), не `ok` и не ноль; `never` — «не из чего считать» | вердиктов нет; есть **неокончательный итог** — месяц идёт или выписки доведены не до конца: число верное за записанный срок, а не за месяц |
| **Догадка не выдаётся за расчёт** | нормы — с `NORM_MIN_WEEKS`; калорийность блюда — оценка ИИ, у домашних блюд погрешность в десятки процентов (Р-03 «Трапезы»); `assumed` (Р-18 «Трапезы») | `NORM_MIN_WEEKS` | срок по истории — с трёх промежутков (Р-27) | идущий месяц не досчитывается прогнозом, а сравнивается по записанному сроку (Р-22, Р-24 «Злотых»); блоки сравнения молчат до порога (Р-21, Р-28 «Злотых») |
| **Не прятать молча** | итог называет, сколько «без категории» (Р-02) | в сравнении категория прошлого — с нулём (Р-55) | фильтр показывает счёт свёрнутого (Р-46, Р-55) | не вошедшее названо (Р-04) |

## Что видно для формы среза — наблюдения, не решение

1. **«Число с основанием» — общий знаменатель всех четырёх.** Каждый показатель среза, вероятно, несёт основание, а не голое число. Это первый кандидат в договор
2. **Показатель бывает «не ясно» и «не известно»** — не ноль. Форма среза должна уметь сказать это без выдумывания числа
3. **Зерно разное:** день, неделя, любой промежуток, месяц, год, «на дату». Общего отрезка, на котором считают все, нет
4. **Каждое денежное число несёт код валюты.** У «Злотых» месяц и капитал — одно число в базовой валюте плюс список не вошедшего без курса; списком по валютам — только долги. База может смениться (Р-41 «Злотых»): старый и новый срезы окажутся в разных валютах. У «Дневников» кода валюты нет вовсе — цена голым числом в рублях: код срезу дописывать самому. **Одна трата бывает в двух приложениях:** стрижка — отметка цикла и расход «Злотых» (Р-35 «Дневников»); сложив их, потребитель посчитает дважды
5. **«Требует внимания» уже одинаково по форме** (`Topic`, `Notice`) — самая готовая часть. Но от устройства зависят тема «Трапезы» (что сказать) и тема «Дневников» (когда спросить), у «Делу Время» идущий таймер — не запись. **Тексты тем несут названия и диагнозы** — для чужого глаза тема идёт без текста
6. **Свежесть — не одни часы, а несколько.** Когда посчитано; по какое число записаны данные (у «Злотых» — выписки, `loadedThrough`); есть ли курсы на дату. Прошлый месяц меняется, когда догружают выписку, прошлый капитал — когда подтягивают курсы; прошлые недели «Трапезы» — когда правят справочники, без единой новой записи. Срезу нужна отметка «посчитано по записям по ДД.ММ», а не только время расчёта
7. **«Не известно» — с причиной.** У «отложено» «Злотых» причин две (`no-income`, `covered`), а список незнания отчёта месяца (Р-29 «Злотых», п. 3) даёт ещё: незагруженные дни, позиции без курса, редкие платежи, категории без сравнения. Голый `null` в срезе одно от другого не отличит
8. **Отрезок — явными `from` и `to`**, а не `ГГГГ-ММ`: у «Злотых» есть `periodStartDay`, и «месяц» может перестать быть календарным
9. **Неокончательный итог** — четвёртое состояние рядом с числом, «не известно» и «не ясно»: число верное, но за записанный срок

Для среза переделывать не нужно — `Period` ядра по форме подходит. **Настоящая разница — в смысле:** эпизод относится к промежутку по началу, а не по пересечению. Перевод на `Period` ядра — их уборка своим решением, не условие среза
- **Для чужого глаза:** циклы — счёт позиций по статусам на день, `unset` отдельно от `ok`; `Spent` за промежуток с кодом `RUB` и основанием «`priced` из `marks`»; названия позиций — только названному потребителю. Здоровье — `count`, `closed`, средняя и медианная длительность с основанием `closed`, `healthySince` только на «всё время», открыт ли эпизод и с какого дня; `activityTotals` — `sessions`, минуты и км с оговоркой об основании. Контент — `started`, `done`, `dropped`, `active`, `finished`, `averageScore` со `scored`, `byType`. **Кухня:** у циклов `ratio`, `spread`, `byHistory`, `next`, `overdueDays`, `compareUrgency`, группировки, `spendTree` как дерево, шаблоны, `lastPrice`, планы переименования; у здоровья `byMonth`, `gaps`, `symptoms`, `series` и всё про метрики, `recentSymptoms`, `episodeStates`; у контента `byScore`, `top`, `byMonth`, фильтры и группировки, `staleDays` с порогом

**Позиции сессии «Дневников» — материал к решению о форме среза, решает человек:**

- **Здоровье — ступени, как у денег в Я-13:**
  1. всегда, без подробностей — открыт ли эпизод, число просроченного в циклах, число зависшего в «смотрю»;
  2. названному потребителю — счёты эпизодов и дни болезни в промежутке, без названий, симптомов и заметок;
  3. измерения — вес, давление — не в срез, пока их не попросит названный потребитель; из §7 не просит никто.

  Никогда: название эпизода, `note`, симптомы, `comment` контента
- **`contentStats` по промежутку — можно, новым решением «Дневников»:** `contentStats(entries, period)` на `Period` ядра плюс счёт записей, чья месячная дата лишь частично попадает в промежуток — «ещё N с точностью до месяца», никогда не первым числом. Месяц и год считаются точно — это ровно зерно, которое просит «Делу Время»; неделя почти всегда «не известно». «Досмотрено» — нынешний статус начатого в промежутке, а не событие внутри него
- **«Дни болезни в промежутке»** для первого факта обзора «Делу Время» — новый расчёт: пересечение эпизодов с промежутком, наложения склеиваются, открытый длится до сегодня; новое решение «Дневников», а не вынос готовой функции
